# 건축물대장 조회시스템

서울 지번 또는 도로명 주소를 국토교통부 건축HUB 건축물대장정보 서비스로 조회하는
Streamlit 앱입니다. 기존의 정적 CSV 스냅샷 대신 공식 API를 우선 사용하며,
일반/집합건축물의 용도·면적·주차와 층별 용도·면적에 집중해 빠르게 보여줍니다.

## 지원 범위

- 서울 25개 구의 현행 법정동 467개 지번과 산번지 (기본 조회 지역)
- 동 없이 지번만 입력해 서울 전체의 같은 지번 건축물 검색
- 도로명·건물번호로 지번을 연결하여 건축물 조회
- 제1·2종 근린생활시설, 주택, 오피스텔, 업무시설, 공장 등 용도 제한 없는 조회
- 일반건축물·집합건축물 표제부
- 층별 면적 및 용도
- 세대·가구수와 별도로 표시하는 총 호실개수 (대장 호수 우선, 명시 개수만 참고 계산)
- 선택적으로 VWorld GIS건물통합정보의 위반건축물 **참고값**
- 사용자가 누를 때만 실행되는 서울부동산정보광장 **위반건축물 참고 확인**

## 서울 조회

서울 앱 <https://seoul-building-register.streamlit.app/>에서 `332-37`, `737`,
`산1-5`처럼 지번만 입력하면 서울 전체에서 같은 지번의 주소를 **빠른 검색**합니다.
주소·건물명·용도·연면적·주차대수 목록에서 구를 좁히고 주소를 선택해
건물 용도와 층별 상세 정보를 조회할 수 있습니다. `737`은 부번 없는 일반 737번지,
`산737`은 산번지만 검색하며, `737-1`은 별도의 지번입니다.

`역삼동 737`, `금천구 독산동 1000`처럼 법정동과 지번을 함께 입력하면
기존처럼 바로 상세 조회합니다. `신사동`은 강남구·은평구,
`신정동`은 양천구·마포구에 있으므로 구까지 입력해야 합니다.
행정동(예: 독산1동)과 호실 번호는 지번 입력에 사용하지 않습니다.
수원 앱은 기존 주소 `https://won-top-finder-work.streamlit.app/`에서 그대로 사용합니다.
수원은 `main` 브랜치, 서울은 `deploy/seoul` 브랜치의 `app.py`를 각각 별도
Streamlit 앱으로 배포합니다. 서울 변경을 `main`에 병합하지 않습니다.

### 도로명 주소 검색

같은 입력창에 `은천로5길 26`, `강남구 테헤란로 152`,
`서울특별시 관악구 은천로5길 26 (봉천동)`처럼 입력할 수 있습니다.
도로명·건물 본번/부번·지하 여부를 정확히 비교하고, 입력한 구가 있으면 구까지
일치하는 서울포털 주소 후보만 사용합니다. PNU의 현행 서울 법정동 코드와 구를
검증하여 지번으로 연결하고 기존 건축HUB 상세 조회와 서울포털 링크에 전달합니다.
예를 들어 `은천로5길 26`은 `관악구 봉천동 645-77`로 조회합니다.

확인된 주소가 하나면 바로 조회하고, 여러 지번이거나 일부 목록만 확인되었으면
사용자가 선택합니다. 입력한 주소의 동·호수는 제외해야 하며, 복사한 주소 끝의
괄호 설명은 지원합니다. 검색 결과의 호실 문서는 건물번호를 보존한 채 중복 지번으로
합칩니다. 주소를 찾지 못하거나 통신이 실패해도 다른 지번·서울 전체로 자동 검색하지
않습니다. 연결 결과를 화면에 표시하며 도로명 변경·색인 누락 시 지번으로 조회할 수 있습니다.
주소 변환은 1시간 캐시하고 빈 결과·불완전한 결과·오류는 보관하지 않습니다.

### 지번만 입력하는 빠른 검색

기본 검색은 서울포털이 사용하는 `wisenut/totalSearch.do`에서 주소 후보를 먼저
찾고, **PNU의 법정동·일반/산·본번·부번이 정확히 일치하는 후보만** 건축HUB
표제부로 확인합니다. 건물명·도로명·`INFO_YN`이 비어 있어도 후보에서 제외하지
않습니다. `332-37`은 실측 후보 7곳으로 기존 467개 동 조회를 줄이며,
동일 PNU의 검색 문서는 합칩니다. 상세 정보는 기존 건축HUB 조회를 사용합니다.

서울포털 목록은 100건씩 다음 페이지도 읽습니다. 빠른 응답을 위해 최대 10페이지,
약 8초의 탐색 예산을 두고, 목록 변경·반복·코드 누락·상한 도달 시 일부 후보라고
명시합니다. 포털의 주소 색인은 완전한 건축물대장이 아니므로, 정상적인 빠른 검색도
신규·누락 주소까지 모두 포함한다는 뜻은 아닙니다. `누락 주소까지 전체 동 확인`을
누르면 기존 467개 법정동 검색으로 확장하며 이미 확인한 주소는 재사용합니다.
주소 검색 장애나 후보가 없는 경우에도 자동으로 느린 전체 조회를 시작하지 않습니다.
일시적인 주소 검색 통신 오류·잘못된 JSON 응답은 같은 페이지를 한 번 더 요청합니다.
다음 페이지가 계속 실패하면 이미 확인한 후보를 부분 결과로 보존하고, 부분 결과는
주소 캐시에 남기지 않아 다음 검색에서 다시 확인합니다. 빈 주소 후보도 캐시에서 제거합니다.

후보 검색은 1시간·최대 512개 검색어, 건축HUB 성공 결과는 인증키별로
24시간·최대 10,000개 지번까지 보관합니다. 실패는 캐시하지 않습니다.
건축HUB 작업 4개를 병렬 처리하며 새 지번 요청 시작은 초당 최대 4개로 제한하고
작업별 연결을 재사용합니다. 전체 동 확인은 수 분 걸릴 수 있으며 시간 제한·연속
장애·한도 초과로 멈추면 확인 결과와 미확인 주소를 구분해 이어서 확인할 수 있습니다.
API가 제공하지 않는 건물의 존재나 위반 여부까지 보장하는 검색은 아닙니다.

### 상세 조회 속도와 일시 오류 복구

기본 조회는 **표제부와 층별개요 2종만 동시에 요청**합니다. 기본정보가 먼저 도착하면
용도·면적·주차를 즉시 표시하고, 층별 용도·면적은 도착하는 대로 완성합니다.
층 자료가 표제부에 직접 연결되지 않을 때만 기본개요를 추가로 받아 관리번호 관계를
확인합니다. 관계가 불명확한 층은 별도 표에 표시하며 특정 건물에 임의로 합치지 않습니다.
같은 층의 용도·면적이 다른 행은 각각 보존합니다.

총괄표제부·전유부·전유공용면적·인허가 자료는 기본 조회에서 요청하지 않습니다.
세움터·정부24 열람과 공시가격·호별면적 메뉴는 서울 화면에서 제거했습니다.
서울포털 참고 확인은 건물·층별 결과 아래 접힌 영역에서 사용자가 누를 때만 실행합니다.

인증키·중계 경로별 동시 요청은 최대 3개, 새 요청 시작은 초당 4개로 제한합니다.
직접 요청은 연결 2초·응답 4초 제한과 최대 1회 재시도, 중계는 연결 2초·응답 5초
제한과 1회 시도를 사용합니다. 일시 오류가 계속되면 해당 항목만 여유 있는 복구 경로
(직접 응답 12초, 서명 중계 응답 15초)로 한 번 더 확인합니다. 중계가 설정돼 있으면
복구는 중계부터 사용해 실패한 직접 연결을 반복하지 않습니다. 이 값은 각 연결/응답 제한이며 전체 조회 완료시간을
보장하지 않습니다. 대용량 건물은 모든 층을 보존하도록 다음 페이지도 받습니다.

정상 응답은 지번·항목별 최대 24시간 재사용하고 동일 항목의 동시 요청은 하나로
합칩니다. 캐시는 최대 768개 항목·50,000개 행이며, 빈 층별 항목은 5분만 보관합니다.
빈 표제부·실패 응답은 캐시하지 않습니다. 전체 화면 결과를 따로 장기 캐시하지 않아
`누락된 상세 정보 다시 확인`은 성공 항목을 재사용하며 실패 항목만 다시 요청합니다.
도로명·지번 선택 상태도 유지합니다.

API 오류 01(내부 처리 오류)·05(서비스 시간초과)와 일시 통신 오류는 자동 복구 대상입니다.
인증·일일 한도·잘못된 요청은 다른 경로로 재시도하지 않습니다. 표제부가 빈 목록을
반환하면 XML 형식으로 한 번 더 확인합니다. 지번 숫자의 정수/앞자리 0 표기 차이는
정규화하되, 다른 지번·산번지나 코드 누락을 동일 주소로 간주하지 않습니다.
층별 일시 지연은 자료 없음과 구분합니다.
필수 표제부 오류·인증·일일 한도 오류는 조회 실패로 표시합니다. 화면의 기본정보와
층별 완료시간은 실제 대기시간이며 API 상태·캐시 여부에 따라 달라집니다.

서울 법정동은 [행정안전부 행정표준코드관리시스템](https://www.code.go.kr/stdcodesrch/codeAllDownloadL.do)의
법정동 전체자료 중 `존재` 상태의 서울 법정동만 사용합니다. 출처·확인일·원본 ZIP의
SHA-256은 `data/seoul_legal_dongs.json`에 기록됩니다. 코드 갱신은
`python scripts/update_seoul_legal_dongs.py`로 실행하고 변경 목록을 검토합니다.

서울 결과에는 수원 CSV와 경기부동산포털 보조 조회를 사용하지 않습니다.
위반건축물은 서울포털 건축물 목록 표시 여부와 반환된 `violBldYn` 참고값을
확인합니다. 설정된 경우 VWorld
참고조회도 제공합니다. 건축HUB 인증키는 새 Streamlit 앱의 Secrets에 별도 설정하며,
기존에 승인된 키를 재사용할 수 있습니다. 키를 코드에 저장하지 않습니다.
데이터가 없는 지번이나 제공되지 않는
세부 항목까지 조회를 보장하지 않으며, 전체 건축물을 미리 일괄 수집하지 않고
입력한 지번에 대해 API가 제공하는 건물·층 정보를 조회합니다.

### 서울포털 위반건축물 참고 확인

[서울부동산정보광장 공식 안내](https://land.seoul.go.kr/land/wskras/generalInfo.do)에
따르면 2025년 9월 12일 연계 방식 변경 이후 위반건축물 정보가 표시되지 않습니다.
앱은 이 안내를 다음과 같이 적용합니다.

- 정확히 같은 지번의 건축물 목록이 표시되면 표시 사실과 목록별 위반 참고값만 제공합니다.
- 정상 응답의 목록이 비어 있으면 `건축물정보 미표시 — 추가 확인 필요`로 표시합니다.
- 명시적인 위반 표시가 반환되면 해당 참고 표시를 알립니다.
- 통신 실패·잘못된 응답·다른 지번 반환은 별도 오류로 표시하며 미표시로 바꾸지 않습니다.
- 표시된 건물 외에 숨겨진 건물·전유부가 있을 수 있으므로 `위반 없음`으로 확정하지 않습니다.

공개 페이지가 사용하는 `getBldrgstList.do`에 사용자가 요청한 한 지번만 조회하며,
10분 캐시와 연결·응답 타임아웃을 사용합니다. 공식 지원 OpenAPI는 아니므로 포털
변경 시 동작이 중단될 수 있으며 그때는 원본 사이트·발급 대장을 사용합니다.

`서울부동산정보광장 직접 보기`는 조회한 자치구·법정동·산 여부·본번·부번을
전달하여 해당 지번의 검색 결과를 바로 엽니다.

### 총 호실개수와 자료 미확인

표제부의 `hoCnt`가 양수이면 세대수(`hhldCnt`)·가구수(`fmlyCnt`)와 별도 카드로
표시합니다. `hoCnt`가 0·미기재일 때 상세용도의 `다중주택(16실)`처럼 명시된 개수,
또는 모든 관련 층에서 확인되는 `오피스텔(6호)` 등의 합계만 참고값으로 표시합니다.
같은 층의 중복 개수·누락된 층·불명확한 건물 연결은 전체 호실수로 추정하지 않습니다.
세대·가구수, 면적, 층별 행 수로 호실수를 계산하지 않으며 근거가 없으면 확인 불가입니다.
대장 호수와 참고 합계 모두 실제 내부 방 수를 실측한 값은 아닙니다.

모든 용도의 건물을 같은 API로 요청합니다. 대장이 확인되지 않을 때는 서울 주소 색인의
동일 PNU에 등록된 도로명 주소를 별도로 보여주며, 주소 문서를 건축물대장으로 바꾸거나
그 문서 수를 건물 수로 표시하지 않습니다. 신림동 1414-11처럼 주소 목록과 대장 제공
여부가 다른 경우도 건물 없음·위반·주택 외 제외로 단정하지 않습니다. 확인된 API 수신
건수와 지번 일치 건수는 조회 상태에서 볼 수 있습니다.

### Streamlit Cloud 연결 중계

공식 건축HUB URL은 `https://apis.data.go.kr/1613000/BldRgstHubService`입니다.
현재 운영 배포는 무료 Supabase Edge Function을 서울 리전에서 사용합니다.
앱은 먼저 공식 API에 직접 연결하고, 연결·TLS·프록시·응답 읽기 지연처럼
사용 가능한 응답을 받지 못한 전송 장애에는 서명된 중계로 자동 전환합니다.
중계의 일시적인 타임아웃·`408`·`429`·`5xx`도 새 서명으로 한 번 더
자동 재시도합니다. 인증·일일 할당량·요청 파라미터 오류는 반복해도 복구되지
않으므로 재시도하거나 중계로 숨기지 않습니다.

Supabase에는 `DATA_GO_SERVICE_KEY`만 secret으로 저장합니다. Streamlit은 기존
`BUILDING_HUB_API_KEY`를 그대로 유지하며, 별도 HMAC secret 없이 같은 키에서
도메인 분리된 서명키를 서버 내부적으로 파생합니다. API 키 원문은 중계 요청에
포함되지 않습니다. 배포된 공개 URL은 `src/relay_config.py`에 들어 있어
Streamlit Community Cloud의 Secrets 화면을 따로 수정하지 않아도 GitHub 재배포로
반영됩니다. 함수 코드는 `supabase/functions/building-hub-relay/`에 있으며,
`X-Region: ap-northeast-2`로 서울 실행을 요청합니다. Cloudflare Worker와 FastAPI
구현은 장애 시 사용할 수 있는 대체 배포안으로 남겨 둡니다.

## 데이터 출처와 한계

- 건축HUB 건축물대장정보는 월간 갱신이며 발급 대장과 시차가 있을 수 있습니다.
- 층별 정보가 지연되면 받은 기본정보를 표시하고 지연과 빈 자료를 구분합니다.
- 지번 5개 항목을 검증하고 관리번호의 공식 관계로만 층을 건물에 연결합니다.
- 용도·면적이 다른 같은 층의 행은 유지하며, 누락 값을 0으로 추정하지 않습니다.
- 건물별 정보와 연결 미확인 층 자료를 구분하며 서로 합산하지 않습니다.
- 서울포털 표시 여부와 VWorld 자료는 위반 여부의 참고자료이며 법적 판정이 아닙니다.
- 이 앱의 결과는 공식 증명서가 아닙니다.

## Streamlit Cloud 건축HUB 연결 장애: 무료 중계 경로

Streamlit Community Cloud에서 `apis.data.go.kr` 직접 연결이 `connect_timeout`, DNS/connection, TLS 단계에서만 실패할 경우, 앱은 선택적으로 서명된 중계로 전환할 수 있습니다.

추가 결제 없는 현재 운영 경로는 `supabase/functions/`의 Supabase Edge Function입니다. 기존 `BUILDING_HUB_API_KEY` 직접 호출이 항상 1순위이며, 중계는 건축HUB 또는 부동산공시가격알리미의 네트워크 연결 장애 때만 사용됩니다. Cloudflare Worker와 `relay/`의 FastAPI 구현은 대체 배포 옵션입니다.

Cloudflare 대체 배포가 필요한 경우에만 다음 부트스트랩 명령을 사용할 수 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm 'https://raw.githubusercontent.com/ljs712312-prog/find/main/scripts/bootstrap_cloudflare_worker.ps1' | iex"
```

Supabase 운영 URL은 이미 `src/relay_config.py`에 반영되어 있습니다.
